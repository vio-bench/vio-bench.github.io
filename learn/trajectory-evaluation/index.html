Trajectory error and evaluation coverage

Understand ATE, RPE, alignment, and why an error number needs an explicit evaluation interval and denominator.

Prerequisites: Coordinate frames and pose conventions

Establish corresponding poses and output semantics

Compare the same physical sensor frame using a declared pose direction, quaternion convention, position units, and timestamp units. Specify timestamp association, tolerance, interpolation, and the valid reference intervals. Converting a text layout does not apply the camera-to-IMU or marker-to-IMU transform.

Record whether the trajectory contains estimates produced online at each timestamp, states revised by a smoother, or poses corrected by loop closure. OpenVINS recommends collecting the current estimate when evaluating online estimator behavior. These outputs should not be silently mixed in a comparison.

Absolute error depends on the permitted alignment

For one run, define position error from the aligned estimate and associated reference. The equation below averages squared Euclidean position errors over K correspondences before taking the square root. Orientation error is a separate quantity, commonly the angle of the relative rotation; declare radians or degrees.

With observable metric scale and a common gravity frame, yaw plus translation removes the usual four global gauge freedoms of VIO. SE(3) also fits roll and pitch; Sim(3) additionally fits scale. Specify the allowed transform and fitting poses. The suitable policy depends on the estimator and motion assumptions, and each policy measures a different remaining error.

Relative error requires a pair convention

RPE compares estimated and reference relative motions for a specified set of pose pairs. Declare whether separation is measured in time, traveled distance, or frames, the interval and tolerance, and how starting poses and endpoints are selected. State whether distances come from the reference or estimate.

Report translation and rotation separately and name the statistic across pairs, such as median or RMSE. OpenVINS evaluation reports distance-segment RPE summaries; their pair counts differ from the number of trajectory poses. An error in meters is not a percentage drift, and an angle in degrees is not degrees per meter. Document any segment-length normalization.

Keep the levels of averaging explicit

OpenVINS distinguishes a trajectory RMSE for each run, a mean of run RMSEs, and a time-indexed RMSE across repeated runs. These answer different questions. Averaging sequence-level RMSEs is another level: it gives each contributing sequence equal weight unless a different weighting is specified.

The arithmetic mean of run RMSEs is generally different from pooling all squared pose errors and then taking one square root, even when runs contain equally many samples. Keep pose counts, RPE pair counts, contributing runs, and contributing sequences separate. Report the finite-value rule and missing contributors. This lesson defines the distinction; it does not change the historical VIOBench aggregation.

Report evaluated extent and missing outcomes

A low error over the associated output does not establish accuracy over the entire recording. Report initialization, output gaps, final output time, eligible reference intervals, and attempted runs. In this lesson, matched-sample coverage means matched reference samples divided by eligible reference samples; a time fraction or completed-run fraction requires its own denominator.

EPICA also reports a local drift-valid path fraction. Its denominator follows the reference path supplied to that evaluation stage, after the selected association and preprocessing. Keep that fraction separate from missing-recording coverage and successful-run rate. Record the package version, selection rules, thresholds, and global-failure status. Public EPICA 0.1.17 and its live documentation differ in global-gate handling, so do not infer historical VIOBench rules from current documentation.

WORKED EXAMPLE

An estimate matches 800 of 1,000 eligible reference samples and has 0.05 m position RMSE on those matches. What can you report?

Explanation

Under this sample-based definition, matched-sample coverage is 80%, and position RMSE is 0.05 m over the 800 matches. This does not establish the error over the missing 200 samples or imply 80% time coverage.

Before you begin: Understand what initialization must recover

Both approaches reconcile measurements

Suppose an estimated state predicts where a tracked feature should appear. The difference between the observed and predicted pixel location is a residual. Inertial measurements produce motion constraints as well. Filtering and optimization both use these constraints and their uncertainty; their names alone do not determine which observations are used.

The equation below is a schematic weighted least-squares objective. Here x collects estimated variables, r_i is a measurement residual, and Σ_i is its covariance. The weighting matters: a residual in pixels and one in meters cannot be compared by adding their raw squared magnitudes.

x* = arg min_x ∑_i r_i(x)ᵀ Σ_i⁻¹ r_i(x)

Filtering carries an estimate and covariance

An extended Kalman filter propagates an estimate and covariance, then updates them with new measurement constraints. An MSCKF also retains selected past poses so a feature observed across several images can constrain relative motion. It does not have to retain every observed landmark as a permanent state variable.

OpenVINS explains how projecting a linearized feature residual into the left nullspace of its feature Jacobian removes explicit sensitivity to that feature's position error. The remaining constraint can update the retained navigation states. This is a concrete mechanism behind the MSCKF formulation.

A sliding window revisits retained states

A sliding-window optimizer jointly adjusts states within an active time window. VINS-Mono combines visual constraints with preintegrated inertial constraints in such a formulation. Older variables are removed as the window advances, while their influence is summarized through marginalization.

The window size, number of tracked features, solver iterations, linearization choices, and marginalization policy affect both computation and the estimate. Optimization is not automatically more accurate, and filtering is not automatically faster under different input or implementation conditions.

Compare the actual system configuration

Record camera mode, image resolution, input rate, feature settings, calibration options, and enabled mapping components before comparing two systems. Loop closure belongs to an additional global correction process and should be identified separately from the local VIO estimator. Investigate residuals and timing components before attributing an observed difference to the broad estimator family.

WORKED EXAMPLE

Two systems use the same estimator family but different image resolutions and feature counts. Can a timing difference isolate the effect of the estimator formulation?

Reveal the explanation

No. The input and configuration differences also change computational work. First compare a documented common condition, then vary one setting to study its effect.

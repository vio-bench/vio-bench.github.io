Run OpenVINS on EuRoC

From a stereo image sequence and IMU measurements to a saved trajectory.

Guide contents1. Prepare the environment2. Build the public upstream project3. Download and inspect the dataset4. Select the EuRoC calibration5. Launch, visualize, and play6. Inspect and evaluate the trajectoryTroubleshootingOther implementations
Ubuntu 20.04 · ROS 1 Noetic · Bash

This guide follows the official OpenVINS EuRoC tutorial, from installing the estimator to saving and evaluating a trajectory. Run these commands in the documented Linux environment.

Commands reviewed 2026-09-06; source revision 69488123ed93. This guide has not been executed as part of this website release.

Prerequisites

  • Ubuntu 20.04 with ROS 1 Noetic desktop-full installed using the upstream ROS1 installation instructions. Desktop-full supplies ROS tools and RViz; use Bash terminals. This is the upstream tutorial environment, not a native macOS workflow.
  • Git, a C++ build toolchain, CMake, catkin_tools, Eigen, Boost, Ceres, OpenCV with contrib modules, and the ROS dependencies listed below. Include the Python 3 packages for the evaluation plots used in step 6.
  • The EuRoC V1_01_easy ROS1 bag, downloaded from the official dataset source and saved as ~/datasets/euroc/V1_01_easy.bag.

1. Prepare the environment

First install ROS 1 Noetic desktop-full on Ubuntu 20.04 using the linked upstream ROS1 instructions. After that, the commands below install the build and plotting dependencies used by this guide. OpenVINS package manifests also require cv_bridge, image_transport, and cmake_modules; they are included explicitly. Do not continue until installation succeeds.

  • OpenVINS installation
  • Evaluation dependencies
BASH
sudo apt-get update
sudo apt-get install git build-essential cmake \
  python3-catkin-tools python3-osrf-pycommon \
  libeigen3-dev libboost-all-dev libceres-dev \
  libopencv-dev libopencv-contrib-dev \
  ros-noetic-cv-bridge ros-noetic-image-transport ros-noetic-cmake-modules \
  python3-dev python3-matplotlib python3-numpy python3-psutil python3-tk
source /opt/ros/noetic/setup.bash

2. Build the public upstream project

Start in a Bash terminal with ROS sourced. Use a new workspace, then build all OpenVINS packages, including ov_eval. Continue only after catkin reports a successful build. Record the actual cloned commit with the experiment; the source revision shown on this page records the version reviewed for this guide.

BASH
source /opt/ros/noetic/setup.bash
mkdir -p "$HOME/workspace/catkin_ws_ov/src"
cd "$HOME/workspace/catkin_ws_ov/src"
git clone https://github.com/rpng/open_vins/
cd ..
catkin build
source devel/setup.bash
git -C src/open_vins rev-parse HEAD

3. Download and inspect the dataset

Create ~/datasets/euroc if necessary, then download the V1_01_easy ROS1 bag through the official links and save it as ~/datasets/euroc/V1_01_easy.bag. Run the inspection command after the download completes. This remains an explicit manual download step; the commands below do not fetch the large dataset. The bag contains stereo images and IMU measurements.

PREPARE THE FOLDER
mkdir -p "$HOME/datasets/euroc"
  • Official EuRoC dataset
  • OpenVINS download links
BASH
source /opt/ros/noetic/setup.bash
rosbag info "$HOME/datasets/euroc/V1_01_easy.bag"
Expected output and verification

Image topics /cam0/image_raw and /cam1/image_raw, plus /imu0, should be present.

4. Select the EuRoC calibration

config:=euroc_mav selects the supplied estimator settings, IMU noise/topic file, and camera–IMU calibration. This run explicitly uses two cameras with stereo tracking. For your own sensor, these files must be replaced with its calibration and topic names.

  • EuRoC configuration
  • config/euroc_mav/estimator_config.yaml
  • config/euroc_mav/kalibr_imu_chain.yaml
  • config/euroc_mav/kalibr_imucam_chain.yaml

5. Launch, visualize, and play

Use four separate Bash terminals; each block sources its own environment and does not inherit variables or a working directory from another terminal. Start the estimator and RViz before playing the bag. Trajectory saving is enabled. The upstream recorder replaces an existing estimate.txt at launch, so choose a new filename when preserving repeated runs.

Terminal 1 · ROS master
source /opt/ros/noetic/setup.bash
roscore
Terminal 2 · Estimator + trajectory recorder
source /opt/ros/noetic/setup.bash
source "$HOME/workspace/catkin_ws_ov/devel/setup.bash"
mkdir -p "$HOME/vioverse-runs/openvins-euroc"
roslaunch ov_msckf subscribe.launch config:=euroc_mav max_cameras:=2 use_stereo:=true dosave:=true path_est:="$HOME/vioverse-runs/openvins-euroc/estimate.txt"
Terminal 3 · RViz
source /opt/ros/noetic/setup.bash
source "$HOME/workspace/catkin_ws_ov/devel/setup.bash"
rviz -d "$(rospack find ov_msckf)/launch/display.rviz"
Terminal 4 · Dataset playback
source /opt/ros/noetic/setup.bash
rosbag play "$HOME/datasets/euroc/V1_01_easy.bag"
Expected output and verification

After initialization, RViz should show feature tracks and an estimated trajectory. estimate.txt records the current IMU pose estimates. A saved file alone does not establish a successful full run.

6. Inspect and evaluate the trajectory

After playback finishes and the estimator completes processing, press Ctrl+C in Terminal 2 to close the estimator and recorder. Open a Bash terminal and run the block below. The ground-truth file is included in the public OpenVINS checkout, so no separate GT download or format conversion is needed. For V1_01_easy, upstream documents its recomputed IMU ground truth because of orientation errors in the original release.

  • Evaluation methods
  • V1_01_easy ground-truth note
  • Ground-truth files
  • Reviewed ROS pose direction and timestamps
  • Reviewed trajectory recorder
BASH
source /opt/ros/noetic/setup.bash
source "$HOME/workspace/catkin_ws_ov/devel/setup.bash"
rosrun ov_eval error_singlerun posyaw "$HOME/workspace/catkin_ws_ov/src/open_vins/ov_data/euroc_mav/V1_01_easy.txt" "$HOME/vioverse-runs/openvins-euroc/estimate.txt"
Expected output and verification

The evaluator reports trajectory error statistics and matched samples. Check the timestamp span and evaluated overlap before interpreting an average.

Trajectory text begins with time(s), px, py, pz, qx, qy, qz, qw; covariance entries may follow. In the reviewed ROS recorder, position is the IMU origin expressed in the global frame, and xyzw represents the IMU-to-global Hamilton rotation. These coefficients numerically match the internal global-to-IMU JPL quaternion; do not conjugate the exported file again. Published pose timestamps already use the IMU clock; do not add the camera–IMU offset a second time.

posyaw aligns translation and yaw; record this choice with the result. Do not mix alignment modes when comparing systems.

Troubleshooting

The package is not found.

Confirm catkin build succeeded and source the workspace devel/setup.bash in that terminal.

No trajectory appears.

Check the bag path, image and IMU topics, selected calibration, and initialization messages. Start the estimator before replaying the bag.

No saved trajectory file.

Confirm dosave:=true and that the output directory exists; the default launch does not save a trajectory.

Evaluation gives no useful overlap.

Check seconds versus nanoseconds, quaternion order, pose frame, and ground-truth source. Use the supplied OpenVINS ground truth for this exercise.

Related topics

  • Record the source commit, configuration, bag identity, camera mode, machine, launch command, output span, and alignment setting with the run.
  • Repeat with a single camera only after the stereo route works; use max_cameras:=1 and preserve the changed settings with the result.
  • Follow the calibration tutorial before using your own sensor.

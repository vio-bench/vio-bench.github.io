BENCHMARK / MEASUREMENT NOTES

Keep the context with the number.

The definitions, provenance, and publication limits of the current VIOBench runtime snapshot.

Frozen research snapshot

This page documents one published runtime snapshot. The learning material explains broader evaluation methods; it does not establish an adopted, comprehensive VIOBench evaluation protocol.

Input and platform scope

The records describe monocular runs on LaMAria R_02_easy, with seven reported native-time values for Desktop, seven for Jetson Orin, and six for Jetson Nano. The source does not identify the input conversion variant.

Platform labels are retained from the source. Exact processor, power mode, clock settings, and build details are not provided in this normalized snapshot.

Timing and aggregation

Mean native total time (ms). Unweighted arithmetic mean of per-selected-run native total timing summaries. Native instrumentation boundaries may differ by implementation.

Each source row lists five selected runs. Missing metrics are excluded from the source average; the number of contributing runs for each metric is not reported. Five selected runs is not the number of total attempts or a verified per-metric sample count.

Missing values stay missing

Unavailable values are omitted, never replaced by zero. A missing source row does not establish execution failure or unsupported operation. The snapshot includes only eligible reported records, not all systems in the VIOVERSE catalog.

  • SVO Pro · Desktop: Source row exists; native total was not reported.
  • SVO Pro · Jetson Orin: Source row exists; native total was not reported.
  • ROVIO · Jetson Nano: No corresponding source row in this snapshot.
  • SVO Pro · Jetson Nano: No corresponding source row in this snapshot.

What these records cannot establish

  • This fixed-input snapshot is not a dataset-wide average or an overall system ranking.
  • Native timing is implementation-reported; it is not a harmonized end-to-end latency or a real-time guarantee.
  • The source does not identify the input conversion variant or per-metric contributing run counts.
  • CPU collector normalization is unconfirmed. Reported percentages can exceed 100%; do not interpret them as a fraction of total machine capacity.
  • Process memory is the reported VINS/process value; whether the collector measured RSS or PSS is unconfirmed.
  • No accuracy, coverage, failure-rate, energy, or deployment-capability conclusion follows from these runtime values.

Provenance

All 20 native time values and their CPU and process-memory values were cross-checked against retained source table rows and the frozen CSV checksum. No experiments were rerun.

This release publishes normalized measured records. Individual run logs, trajectories, exact build configurations, and full source artifacts are not published with this snapshot.

Before making a broader comparison

Report the exact input streams and conversion, calibration, estimator mode, build, machine, timing boundary, number of attempted and evaluated runs, output coverage, and treatment of incomplete runs. For trajectory error, also state the physical pose frame, timestamp association, alignment type and fitting interval, and relative-error interval.

Those details allow a reader to distinguish a fast reported component from a usable complete run. Future result releases should attach the per-run evidence and a fixed evaluation protocol.
